# LeadCMS SDK v3.12.0 - Pushes That Say What They Did

A minor release with two fixes for pushes that went wrong quietly. `push-content --yes` now runs without a terminal, and a push that has to ask a question with no one to answer it fails instead of exiting 0 ([#5](https://github.com/LeadCMS/leadcms.sdk/issues/5)). `push-media` now says which files LeadCMS will rename, before and after the upload. A new `--on-media-rename` option lets projects that refer to media by path skip those files or stop on them ([#6](https://github.com/LeadCMS/leadcms.sdk/issues/6)).

## New Features

### `--on-media-rename rename|skip|fail`

LeadCMS normalises the name of every uploaded file. It transliterates the name to ASCII, turns whitespace into `-`, drops every character except letters, digits, `-`, `.` and `_`, turns `_` into `-`, and lowercases the result:

| Local file | Stored by LeadCMS |
| --- | --- |
| `icons/fire_extinguisher.svg` | `icons/fire-extinguisher.svg` |
| `screens/Request_details.png` | `screens/request-details.png` |
| `screens/chart@2x.png` | `screens/chart2x.png` |

`push-media` and `push` accept a new option that sets what happens to such files:

| Mode | Effect |
| --- | --- |
| `rename` (default) | Upload, then rename the local file to the stored name, as before. |
| `skip` | Leave such files out of the push and list them; everything else is pushed. |
| `fail` | Push nothing and exit 1 while any such file is pending. Also applies with `--dry-run`, so CI can check before pushing. |

```bash
npx leadcms push-media --dry-run --on-media-rename fail
```

### Renames shown before the upload

`status`, `status-media`, `push`, `push-media` and their `--dry-run` predict the stored name and mark each file that will change:

```
✨ 1 file(s) to upload:
   + icons/fire_extinguisher.svg → fire-extinguisher.svg (1.20KB)

⚠️  LeadCMS will store 1 file under the name marked →, and the local file is renamed to match.
   Links in CMS content follow; references in site code, styles or generated files do not.
   To keep names stable, rename it in the project first, or push with --on-media-rename skip|fail.
```

The prediction is exact for ASCII names. For names in other scripts, such as Cyrillic or CJK, the predicted name can differ slightly from the one LeadCMS picks, but such a file is always flagged. Renaming it to the predicted name keeps LeadCMS from changing it. With image optimisation on, a changed extension (for example `.png` to `.webp`) depends on server settings and is only reported after the upload.

## Bug Fixes

### Fixed: `push-content` ignored `--yes`

The help listed `--yes, -y` for `push-content`, but the command never read it, and `assumeYes` did not skip the final `Proceed with syncing N changes?` confirmation. `push-content --yes` now creates missing content types from their auto-detected defaults and pushes without asking, as `push --yes` already did.

### Fixed: a push with no terminal exited 0 having pushed nothing

When a push needed an answer and stdin was closed (`< /dev/null`, most CI runners), the prompt never settled. Node ran out of work and exited 0, which CI read as a successful push. Every push prompt now fails when stdin closes before an answer arrives. The command exits 1 and says how to run without the prompt:

```
❌ Push failed: Cannot ask "Proceed with syncing 1 changes to LeadCMS? (y/N):": standard input closed before an answer arrived (no terminal attached?). Pass --yes (-y) to push without prompts.
```

This covers `push`, `push-content`, `push-media` (the hint names `--force`) and the author-email prompt of `push-comments` (the hint says to set `authorEmail`). Piped answers such as `echo y | npx leadcms push-content` still work.

### Fixed: media renames were barely visible after the push

After each upload, `push-media` renamed the local file to the stored name and logged only `↳ Reconciled: Server changed: name`. Each rename is now printed with its new name, and the push ends with a list and what to do next:

```
[1/4] ✓ Uploaded icons/fire_extinguisher.svg
  ↳ Renamed locally: icons/fire_extinguisher.svg → icons/fire-extinguisher.svg
...
📛 3 media files renamed locally to the name LeadCMS stored:
   icons/fire_extinguisher.svg → icons/fire-extinguisher.svg
   screens/Request_details.png → screens/request-details.png
   screens/chart@2x.png → screens/chart2x.png
   Run `leadcms pull-content` to get the content links LeadCMS updated,
   and update references in site code, styles or generated files yourself.
```

`push` prints the same list at the end. `pushMedia()` returns the renames in `renamed`, and the files left out with `skip` in `skippedRenames`.

### Fixed: a local rename could overwrite another media file

`a_b.png` and `a-b.png` are both stored by LeadCMS as `a-b.png`. Pushing both overwrote the local `a-b.png` with the content of `a_b.png`. The local rename is now refused with a warning, and both files keep their content.

## Test Coverage

- 1552 tests passing across 81 suites
- New `prompt` suite: piped answers, stdin closing before an answer, a shared interface closed after an earlier answer, and the error text
- New `push-content-non-interactive` suite: `assumeYes` pushes and creates missing content types without opening stdin; a closed stdin fails at the content-type prompt and at the confirmation; a piped `y` still pushes
- New `media-rename` suite: the server's naming rule (including the three names from #6), `serverName` on creates and updates, the status notice, the rename report and summary, the collision guard, `skip` and `fail` (including with `--dry-run`), and `--on-media-rename` parsing

## Upgrade Notes

**Scripts that pipe answers into a push** keep working. If they pipe `y` only to get past the prompts, use `--yes` instead.

**CI jobs that run a push without `--yes`** (or `push-media` without `--force`) and no terminal used to exit 0 without pushing; they now exit 1. Add `--yes` / `--force`, or treat the failure as the signal that the job was not pushing anything.

**Projects whose code or build refers to media by path** should rename files to the stored form before pushing. Run `npx leadcms status` to see them, or add `--on-media-rename fail` to the CI push to catch new ones.
