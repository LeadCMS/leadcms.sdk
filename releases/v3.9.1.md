# LeadCMS SDK v3.9.1 - Redirect Maps nginx Will Load, Sequences Counted Once

A patch release fixing three ways the SDK produced output that looked fine and was not: a redirect map nginx refuses to start on, redirect entries that could never match a request, and a sequence reported as two separate changes.

## Bug Fixes

### Fixed: redirect paths losing the leading slash on a round trip

The API canonicalises every path-ish redirect field with `Trim().Trim('/')`, so `fromPath: /versions/6-6/` comes back from a push/pull round trip as `versions/6-6`. `generate-redirects-map` emitted `InternalPath` sources and targets verbatim, which broke them in both directions:

```nginx
# before — neither line does anything useful
"versions/6-6" "help-center";
```

A `map $uri` key without a leading slash can never match, because `$uri` always has one. And a target without one is concatenated straight onto the host by the usual `$scheme://$http_host$redirect` construction, producing `https://example.comhelp-center`. Both failures are silent: nginx loads the map, and every one of those redirects quietly does nothing.

Sources and targets are now rebuilt as site-root paths:

```nginx
"/versions/6-6" "/help-center";
```

Only the leading slash is restored. A path's *trailing* slash is authored intent — under `trailingSlash: "strict"`, `/page` and `/page/` are deliberately distinct sources — so it is passed through untouched even though the round trip may already have dropped it. Where a redirect targets a content page, prefer `fromSlug` / `toSlug`: those are re-rendered through `redirects.pathPattern` and survive the round trip whole.

External `toUrl` targets and protocol-relative URLs are left alone.

### Fixed: duplicate redirect sources producing a map nginx refuses to start on

Two redirects resolving to the same source were both written to the map file. An nginx `map` block rejects a repeated key outright:

```
[emerg] conflicting parameter "/versions/"
```

That is not a degraded redirect — the server does not start. The `trailingSlash: "both"` expansion already de-duplicated the variants it added, but two entries authored with the same source passed straight through.

`generate-redirects-map` now keeps the first entry per source and reports the rest:

```
⚠️  Duplicate 301 source "/versions/" — keeping "/help-center/", dropping "/versions-6-26/"
    nginx refuses to start on a repeated map key; resolve this in redirects.yaml.
```

It also warns when one source appears as both a 301 and a 302. That is legal nginx, but the 301 map is consulted first, so the 302 can never fire.

### Fixed: a sequence reported as both "updated locally" and "added remotely"

`leadcms status` could list the same sequence twice:

```
🔗 Sequences (2 changes):
      added remotely:   Trial Expiration Reminder
      updated locally:  Trial Expiration Reminder (ID: 1)
```

Local and remote sequences are paired by `getRemoteMatch`, which tries name+language, then the remote's `metadata.json`, then the local id. The scan for untracked remotes afterwards used only a `language:name` key, so any sequence paired through the metadata map — one whose language drifted from `en-US` to `en`, say — was counted once as an update and again as a new remote sequence. Both status and push now skip every remote a local file has already claimed.

The same key drove `push-sequences --delete`, where the consequence was worse than a confusing count: a sequence could be updated and then deleted in the same run. Sequences were the only entity type missing the id-based guard that content, email templates and segments already had.

## Test Coverage

- 1437 tests passing across 75 suites
- New `sequence-language-drift` suite: a metadata-matched pair reports one operation, is never listed for deletion, and a genuinely remote-only sequence is still reported
- `generate-redirects-map` gains cases for slash restoration on round-tripped paths, untouched external targets, preserved trailing slashes, duplicate-source dropping with its warning, and the 301/302 overlap warning

## Upgrade Notes

**Regenerate your redirect maps** with `leadcms generate-redirects-map` and read the warnings. Any duplicate source that was previously written into the map is now reported and dropped; if your maps were loading before, you had no duplicates and the output is unchanged.

**Check redirects modelled with `fromPath` / `toPath`.** If they were pushed to a CMS and pulled back, their slashes were trimmed and they have not been firing. The leading slash is restored automatically; a trailing slash that mattered has to be re-authored, and converting the entry to `fromSlug` / `toSlug` avoids the problem for good.

**A sequence whose local `language` no longer matches the remote** will now show as a single update rather than two changes. Pushing it aligns the remote; until then the status is accurate but the drift remains.
